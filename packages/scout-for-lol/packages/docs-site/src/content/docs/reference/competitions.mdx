## Criteria

| Criteria             | Ranks by                             | Queue                           |
| -------------------- | ------------------------------------ | ------------------------------- |
| `MOST_GAMES_PLAYED`  | Games played                         | any competition queue           |
| `MOST_WINS_PLAYER`   | Wins                                 | any competition queue           |
| `MOST_WINS_CHAMPION` | Wins on one champion                 | optional; all queues if omitted |
| `HIGHEST_WIN_RATE`   | Win rate, above a minimum game count | any competition queue           |
| `HIGHEST_RANK`       | Peak rank reached                    | `SOLO` or `FLEX` only           |
| `MOST_RANK_CLIMB`    | LP gained across the window          | `SOLO` or `FLEX` only           |

`HIGHEST_WIN_RATE` takes a minimum game count, defaulting to **10**. Rank-based
criteria are restricted to ranked queues because there is no rank to measure in
other queues.

## Window

A competition runs on either an explicit start and end date, or a League season.
Fixed values are interpreted in `analysisTimezone`: the start is local 00:00:00
and the end is the final local millisecond of the selected end date. The default
for a new builder-created competition is the browser's IANA timezone; legacy
rows default to `UTC`.

Status — upcoming, running, finished — is derived from those dates rather than
stored, so correcting a date immediately corrects the status.

## Scheduled updates

| Field                     | Default for legacy rows | New builder default |
| ------------------------- | ----------------------- | ------------------- |
| `scheduledUpdatesEnabled` | `false`                 | `true`              |
| `updateCronExpression`    | `0 0 * * *`             | `0 9 * * *`         |
| `scheduleTimezone`        | `UTC`                   | Browser IANA zone   |

The cron must select exactly one minute and one hour and may fire at most once
per day. `scheduleTimezone` controls cron evaluation independently from
`analysisTimezone`, which controls competition-day boundaries and analysis.
Disabling updates clears `nextScheduledUpdateAt`; enabling an active competition
computes it immediately in the saved timezone.

## Lifecycle

Scout checks competition starts and ends every **15 minutes**. A declarative
Temporal schedule runs a separate dispatcher **every minute**; stage-local Scout
activity workers post interim standings only for enabled, active, due
competitions. Start and final announcements remain mandatory even when interim
updates are disabled. Failed interim posts still advance the next fire.

## Other fields

| Field                | Notes                                                   |
| -------------------- | ------------------------------------------------------- |
| Title                | Required; up to 100 characters                          |
| Description          | Required; up to 500 characters                          |
| Announcement channel | Required; needs Send Messages and Attach Files          |
| Max participants     | Optional cap on the field                               |
| Analysis timezone    | IANA zone for fixed-day and analysis boundaries         |
| Initial player IDs   | Unique guild-scoped tracked players; `JOINED` on create |

Initial entrants and server-wide enrollment require `competitions:invite`.
Enabled or customized schedules require `competitions:schedule`.
