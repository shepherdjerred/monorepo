export const queues = QueueTypeSchema.options.map((id) => ({
  id,
  label: queueTypeToDisplayString(id),
}));
export const regions = RegionSchema.options;

## Queues

These values are what subscription filters allow, what `WHERE queue IN (…)`
accepts in a report, and what `GROUP BY queue` produces. They are compared
exactly, so write them in lower case as they appear here.

<DataTable
  columns={[
    { header: "Value", values: queues.map((queue) => queue.id), code: true },
    { header: "Queue", values: queues.map((queue) => queue.label) },
  ]}
/>

Limited-time queues are only offered in the subscription filter picker while
they are actually live. Tick **Show unavailable queues** to select one ahead of
time.

## League Classic

League Classic is supported as its own mode, not as a normal League match with
different artwork. Riot's `JADE` queue uses queue ID `4310`; Scout maps its
modern champion IDs to the versioned Classic catalog for prematch loading
screens and postmatch reports. The Classic catalog and renderer are separate
from normal `CLASSIC` matches, so ordinary Summoner's Rift games continue to
use normal champion IDs and assets. Classic ARAM Mayhem uses `KIWI_JADE` when
that limited-time queue is active.

:::caution
A match whose queue Scout does not yet recognize does **not** pass a queue
filter. When Riot adds a new queue, filtered subscriptions skip it until Scout
adds the mapping; unfiltered subscriptions post it immediately.
:::

## Regions

These are the values `/track` offers and the dashboard's region selector uses.

<DataTable
  columns={[
    { header: "Value", values: regions.map((region) => region), code: true },
    {
      header: "Region",
      values: regions.map((region) => toReadableRegion(region)),
    },
  ]}
/>

The region is where Riot can resolve the account's Riot ID. Pick the one the
account actually plays on — a Riot ID that resolves in one region will not
resolve in another.
