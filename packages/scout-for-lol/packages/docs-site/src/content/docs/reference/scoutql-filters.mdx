`WHERE` clauses are joined with `AND` and applied to raw rows before
aggregation. `HAVING` applies after aggregation, to selected outputs and
aliases.

## Operators

| Operator          | Use                  |
| ----------------- | -------------------- |
| `=`               | equality             |
| `IN`              | membership in a list |
| `>` `>=` `<` `<=` | numeric comparison   |

## Examples

Ranked games only:

```sql
where queue in (solo, flex)
```

Only games the player won, on one champion:

```sql
where win = true and champion_id = 350
```

Exclude very short games, which distort per-minute metrics:

```sql
where game_duration_seconds >= 900
```

Require a minimum sample before ranking by a rate:

```sql
select games, win_rate
from match_participants
where queue in (solo)
and games >= 10
group by player
order by win_rate desc
```

`games >= <n>` is an aggregate floor, not a raw-row filter — it is the guard
that stops a 1-0 record topping a win-rate leaderboard.

Scope to a competition's participants and window:

```sql
select score
from competition_rank
where competition_id = 42
group by player
order by score desc
render leaderboard
```

## Notes

- Queue values are the ones listed in [Queues and
  regions](/docs/reference/queues-and-regions/).
- `player = "<alias>"` matches the alias your server uses, not the in-game name.
- `placement` applies to Arena.
- Values with spaces must be quoted.
