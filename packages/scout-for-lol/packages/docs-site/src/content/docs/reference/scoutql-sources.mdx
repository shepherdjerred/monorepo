`FROM` chooses the table. `GROUP BY` chooses how its rows are collapsed. Not
every dimension is valid for every source — the last table below is the
authoritative pairing.

`match_participants` is the default choice for almost every report: one row per
tracked player per match.

Sources whose description mentions `competition_id` require that filter — a
query reading them without it will not compile.

Notes:

- `GROUP BY all` collapses everything to one row and cannot be combined with
  another dimension. It is what `kpi_card` expects.
- `GROUP BY group(N)` works only with the `player_groups` source, takes a size
  of 2–5 or `all`, and cannot be combined with another dimension. Group stats
  sum their members, and a win requires every member to have won.
- Two dimensions are allowed for sources that support them, which is what a
  `heatmap` needs.
