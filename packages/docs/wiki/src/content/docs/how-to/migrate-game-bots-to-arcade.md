---
title: How to migrate game bots to Arcade
description: Copy game progress, transfer exclusive Discord account ownership, and preserve a rollback path.
---

Migrate by copying progress first, stopping legacy account owners, and enabling Arcade only after beta acceptance.

1. Build the Arcade image through CI and retain its immutable digest. Prepare private game assets with the [package tools](https://github.com/shepherdjerred/monorepo/tree/main/packages/arcade/runtimes). Keep dumps and generated WASM outside Git and images.
2. Reconcile the [dormant Arcade chart](https://github.com/shepherdjerred/monorepo/blob/main/packages/homelab/src/cdk8s/src/resources/arcade.ts) through the [homelab release procedure](/how-to/cut-a-homelab-release/), selecting `createArcadeDeployment(chart, { controllerActive: false })` in its chart factory. This renders zero controller replicas and a read-only storage preparation job. Wait for that job to complete and its claims to become `Bound`. Populate the private asset claim. The active mode omits this bootstrap job: ZFS cannot mount its read-only claims alongside the controller's writable save and database mounts.
3. Stop both legacy bot deployments through GitOps. Verify their sessions and streaming accounts have disconnected. Retain both original save claims and the original leaderboard database.
4. Download the stopped legacy save roots and database into a private working directory. Retain this raw snapshot. MK64's per-server engine archive links point into the old container: resolve those known links in a separate private copy using the matching legacy image and ROM-derived archive. The native host replaces these engine links when a session starts. Run `packages/arcade/runtimes/prepare-migration.py` with explicit MK64 save, Emerald save, database, and new output paths. The tool verifies every copied save and SQLite integrity. Keep its manifest with the backup.
5. Copy the verified save and database outputs into the corresponding Arcade claims. Preserve their directory structure. Initialize the additive database schema with the Arcade image; startup refuses destructive schema changes.
6. Preserve the command application's ID and OAuth callback when rebranding it as Arcade. Enable Message Content for Emerald chat input. Create the dedicated vault item with the [declared Arcade credential fields](https://github.com/shepherdjerred/monorepo/blob/4de0ddbb63214dab85d775128dd41def4f22dd7e/packages/homelab/src/cdk8s/src/resources/arcade.ts). Include both game streaming users; keep the [Streambot pool](https://github.com/shepherdjerred/monorepo/blob/4de0ddbb63214dab85d775128dd41def4f22dd7e/packages/homelab/src/cdk8s/src/resources/streambot/streambot.ts) separate. Refresh the vault snapshot. Enable controller ownership using the matching image and [Arcade bootstrap](https://github.com/shepherdjerred/monorepo/blob/4de0ddbb63214dab85d775128dd41def4f22dd7e/packages/arcade/packages/backend/src/index.ts). Use the chart's declared ingress, goal grants, and beta selectors. Keep public rollout off during acceptance.
7. Verify four controller ports, menus, match completion, rematches, save persistence, browser playback, and Discord playback for each multiplayer game. Verify Emerald shared commands and goals. Observe one heavy game alongside MK64 or Emerald before expanding rollout.
8. After checking game speed, input latency, audio/video alignment, and sustained operation, apply the [declared production flag behavior](https://github.com/shepherdjerred/monorepo/blob/9bc617d4e1fb0fc16ab814682ec28b63f2108e32/packages/feature-flags/src/managed-flag-inventory.json) through the [Flipt operator procedure](/how-to/check-flipt-flag-inventory/). Read each existing flag and use its current revision when writing. Verify the `prod` Arcade inventory before deploying the [production environment selectors](https://github.com/shepherdjerred/monorepo/blob/9bc617d4e1fb0fc16ab814682ec28b63f2108e32/packages/homelab/src/cdk8s/src/resources/arcade.ts). Keep source checks, CI, artifact publication, ArgoCD reconciliation, and observed behavior as separate evidence.
9. After live acceptance, retire the two legacy game deployments and their unused services, monitors, and secret mirrors through GitOps. Compare rendered manifests to obtain the exact prune inventory. Retire legacy DNS, tunnel bindings, private ingresses, and redirects; publish only Arcade's canonical hostname. Install Arcade in every intended guild before deleting the old Pokémon command application. Keep its streaming user in the Arcade pool.
10. Remove the legacy deployment sources: the storage-only charts and their Applications, the catalog services and environments, the image repositories, and the analytics sites. The Pokémon and Mario Kart packages stay, because Arcade imports their backends. The live Applications carry the retain lifecycle, so removing them from source does not delete them. Verify Arcade's migrated saves and their backups, then delete the legacy Applications, namespaces, claims, and their backups from an exact, reviewed candidate set.

To roll back, stop Arcade through GitOps and verify its streaming accounts are free. Make a new backup of its current saves and database, then restore the prior Arcade image with its matching configuration and secret references through GitOps. Keep one command and save owner. Never restore an old snapshot over progress made after migration.

To change the game streaming pool, update the dedicated vault item's token array.
Wait for its Kubernetes secret to reconcile, then restart the controller through
GitOps after active sessions end. The [pool discovers account IDs and guild membership](https://github.com/shepherdjerred/monorepo/blob/4de0ddbb63214dab85d775128dd41def4f22dd7e/packages/discord-stream-lifecycle/src/pool/userbot-pool.ts)
at login; [Arcade rejects duplicate identities](https://github.com/shepherdjerred/monorepo/blob/4de0ddbb63214dab85d775128dd41def4f22dd7e/packages/arcade/packages/backend/src/credentials.ts)
before admission. Check each account belongs to the intended guilds.
Adding tokens does not raise the [configured session limits](https://github.com/shepherdjerred/monorepo/blob/4de0ddbb63214dab85d775128dd41def4f22dd7e/packages/arcade/packages/backend/src/config.ts).
Keep the old Pokémon command application until Arcade acceptance and guild
installation finish. Retain its streaming user in the Arcade pool.
Keep the original Pokémon vault item while [Temporal still uses its Codex credential](https://github.com/shepherdjerred/monorepo/blob/9e4dae274c1df081041b8995139f69282b8474ca/packages/homelab/src/cdk8s/src/resources/temporal/workers/worker.ts).

## Move the web edge between namespaces

Prepare and verify the replacement before transferring its public ports and hostnames.

1. Add an internal-only edge to the [Arcade chart](https://github.com/shepherdjerred/monorepo/blob/main/packages/homelab/src/cdk8s/src/cdk8s-charts/games/arcade.ts). Give it a backed-up certificate claim and gate Caddy startup until the existing TLS state has been verified. Keep live NodePorts and hostname bindings on the original edge during preparation.
2. Copy persistent certificate and ACME account data directly between the mounted containers. Exclude transient locks. Verify source hashes before and after the copy, destination hashes, and ownership before releasing the startup gate. Do not write certificate keys to a local archive or logs.
3. Validate the replacement's internal HTTPS listener using the public hostname and normal certificate verification. Check Arcade forwarding, unknown-host rejection, health endpoints, and metrics blocking.
4. Before merging the cutover, hold automatic selection for `gitops/root` and `arcade/prod` in Delivery to prevent premature pruning. Settle existing requests first; preserve other metadata and prior settings. Qualify the exact candidate before pausing admission.
5. Pause new game admission with the existing Arcade flag and drain sessions. Complete the guarded infrastructure release that leaves the legacy charts owning only their original claims. Inspect the exact prune inventory: it must contain no PVC or Application deletion. Wait until the legacy NodePorts and hostname bindings are released.
6. Select that same build's Arcade version through Delivery. Root sync waves do not order an independent Delivery request. Follow the [release ownership and recovery procedure](/how-to/cut-a-homelab-release/); do not bypass Delivery-owned selections with a root sync. Verify public TLS, browser authentication, rejection of retired hostnames, and game streaming before restoring both environments' recorded selection settings and the prior admission flag.
7. Remove the temporary startup gate in the cutover chart. Retain the old certificate claim and original game claims as recovery inputs until the legacy deployments are removed. For an edge rollback, release the replacement's ports before restoring the original edge on Arcade's canonical hostname. Preserve current Arcade saves.
