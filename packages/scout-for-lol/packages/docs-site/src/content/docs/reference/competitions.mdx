## Criteria

| Criteria             | Ranks by                             | Queue                           |
| -------------------- | ------------------------------------ | ------------------------------- |
| `MOST_GAMES_PLAYED`  | Games played                         | any competition queue           |
| `MOST_WINS_PLAYER`   | Wins                                 | any competition queue           |
| `MOST_WINS_CHAMPION` | Wins on one champion                 | optional; all queues if omitted |
| `HIGHEST_WIN_RATE`   | Win rate, above a minimum game count | any competition queue           |
| `HIGHEST_RANK`       | Peak rank reached                    | `SOLO` or `FLEX` only           |
| `MOST_RANK_CLIMB`    | LP gained across the window          | `SOLO` or `FLEX` only           |

`HIGHEST_WIN_RATE` takes a minimum game count, defaulting to **10**. Rank-based
criteria are restricted to ranked queues because there is no rank to measure in
other queues.

## Window

A competition runs on either an explicit start and end date, or a League season.
Status — upcoming, running, finished — is derived from those dates rather than
stored, so correcting a date immediately corrects the status.

## Lifecycle

Scout checks competitions every **15 minutes** and, from that check, announces
starts and posts final standings when the window ends. Intermediate standings
posts are not currently dispatched — the scheduled-update path exists but is not
wired into the cron, so a running competition announces only its start and its
result. Use the competition page or a scheduled report for standings in
between.
