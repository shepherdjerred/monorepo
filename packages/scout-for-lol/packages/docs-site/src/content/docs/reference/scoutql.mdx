ScoutQL is the query language used by reports. It is SQL-shaped but not SQL:
the clauses, sources, and outputs are a fixed vocabulary, and a query compiles
to a validated plan rather than to arbitrary SQL.

Keywords are case-insensitive.

## Clause order

```sql
SELECT   <output> [, <output> …]        -- 1 to 20 outputs
FROM     <source>
[WHERE   <clause> [AND <clause> …]]
GROUP BY <dimension> [, <dimension>]    -- 1 or 2
[HAVING  <clause> [AND <clause> …]]
DURING   <period>                       -- required, unless ANALYZE states one
[ORDER BY <output|label> [ASC|DESC]]
[LIMIT   <n>]
[RENDER  <kind> [WITH (<option> = <value>, …)]]
```

`SELECT`, `FROM`, `GROUP BY`, and a time period are required. Omitting `RENDER`
produces a table.

## Time period

Every query states the period it covers. There is no default — a window nobody
states is a window nobody checks, and an answer computed over a narrower period
than the reader assumed looks exactly like a correct one.

```sql
DURING LAST 90 DAYS
DURING BETWEEN '2026-01-01' AND '2026-01-31' IN TIME ZONE 'America/Los_Angeles'
DURING ALL TIME
```

Calendar dates are inclusive, and are UTC days unless `IN TIME ZONE` names an
IANA zone. An `ANALYZE` clause carries its own period, so a query that has one
must not also have `DURING`.

For compatibility, the older WHERE form —
`game_creation_at >= CURRENT_TIMESTAMP - INTERVAL '30 days'`, or `observed_at`
for `prematch_participants` — still means the same thing as
`DURING LAST 30 DAYS`. Prefer `DURING`.

## Functions

Use these in `SELECT` to compute a value, and name the result with `AS`.

```sql
select per_minute(damage_to_champions) as dpm, games
from match_participants
group by player
having games >= 10
during last 30 days
order by dpm desc
render bar_chart with (y = dpm)
```

`HAVING` filters on aggregated outputs, including aliases you define with `AS`.
`WHERE` filters raw rows before aggregation. Filtering on `games` requires
`HAVING` or the aggregate `games >= <n>` form, because a raw row is a single
game.

The maximum row count is a **report setting**, not query syntax. A `LIMIT`
larger than the maximum is capped at execution. The time period, by contrast,
is query syntax: write it as a `DURING` clause.
